# SER GUIDES — CAHIER DES CHARGES MAÎTRE UNIVERSEL

Version : 1.0
Statut : **référence canonique**
Usage : ce document doit permettre de créer n'importe quel futur SER Guide à partir d'un simple sujet, sans redéfinir les règles à chaque fois.

---

# 0. PRINCIPE

Un SER Guide n'est pas un PDF décoratif ni un résumé générique trouvé sur Internet.

C'est un **produit numérique guidé**, compact, crédible, humain et actionnable, conçu pour accompagner une personne depuis une question ou un problème précis jusqu'à un résultat concret.

Exemples de sujets compatibles :
- apprendre l'anglais ;
- démonter une console ;
- lancer une boutique Shopify ;
- s'habiller selon sa morphologie ;
- préparer un déménagement ;
- comprendre une démarche administrative ;
- apprendre à bricoler ;
- cuisiner ;
- progresser en photo ;
- gérer un budget ;
- réparer un appareil ;
- se former à une compétence.

Le sujet change. Le moteur SER reste le même.

---

# 1. MODE D'EXÉCUTION « SUJET SEUL »

L'entrée minimale obligatoire est :

**SUJET : [sujet demandé]**

Si aucune autre précision n'est donnée, exécuter sans demander confirmation en appliquant ces défauts :

- langue principale : français ;
- marché / contexte : France lorsque le sujet comporte des règles, prix, démarches ou plateformes localisées ;
- version anglaise : préparée après la version française si le sujet est exportable ;
- public : cible la plus logique déduite de la recherche ;
- niveau : débutant → autonome, sauf si le sujet implique clairement un niveau différent ;
- format : web-book interactif + export PDF ;
- taille : 28 à 32 pages cibles, **35 pages maximum** ;
- style : premium, humain, contemporain, pratique ;
- objectif : faire obtenir un résultat, pas simplement informer.

Ne poser une question au demandeur que si une ambiguïté empêche réellement d'exécuter correctement ou légalement le sujet.

---

# 2. OBJECTIF PRODUIT

Chaque guide doit répondre à cette phrase :

> « À la fin de ce guide, le lecteur sera capable de ________. »

La promesse doit être :
- concrète ;
- réaliste ;
- mesurable autant que possible ;
- adaptée au niveau de la cible ;
- sans promesse mensongère de revenu, guérison, résultat garanti ou viralité.

Chaque chapitre doit contribuer directement à cette promesse.

Tout contenu qui ne sert ni :
1. la compréhension,
2. la décision,
3. l'action,
4. la vérification,
5. le résultat final

doit être supprimé.

---

# 3. RECHERCHE OBLIGATOIRE AVANT RÉDACTION

Aucun guide SER ne doit être écrit directement depuis la connaissance générale du modèle.

La première phase est toujours une **recherche multi-source actuelle**.

## 3.1 Hiérarchie des sources

Priorité décroissante :

### Niveau A — sources primaires / officielles
Selon le sujet :
- administrations ;
- législation ;
- organismes publics ;
- documentation constructeur ;
- documentation officielle du logiciel / service ;
- organisme scientifique ou sanitaire ;
- normes ;
- universités ;
- organismes professionnels reconnus.

### Niveau B — sources expertes
- documentation technique reconnue ;
- publications spécialisées ;
- organismes sectoriels ;
- revues professionnelles ;
- spécialistes reconnus dont l'expertise est identifiable.

### Niveau C — signaux marché / utilisateurs
- Google Trends ;
- TikTok Creative Center ;
- Meta Ad Library ;
- YouTube ;
- Reddit / forums spécialisés ;
- commentaires ;
- avis clients ;
- marketplaces ;
- FAQ ;
- recherches associées.

Les niveaux C servent à comprendre :
- ce que les gens cherchent ;
- leurs mots ;
- leurs objections ;
- leurs frustrations ;
- les tendances ;
- les formats qui retiennent l'attention.

Ils **ne remplacent jamais** une source officielle pour établir un fait juridique, fiscal, sanitaire, technique ou réglementaire.

## 3.2 Recherche tendances

Pour les sujets commerciaux, lifestyle, créatifs, numériques ou grand public, utiliser si pertinent :

- Google Trends : comparer l'intérêt dans le temps, la saisonnalité et la zone géographique ;
- TikTok Creative Center : tendances, hashtags, vidéos liées, Top Ads, mots-clés et signaux créatifs ;
- Meta Ad Library : publicités actives, angles marketing, offres, créatifs, messages ;
- YouTube : tutoriels récents, requêtes fréquentes, vidéos d'experts et chaînes officielles ;
- moteurs de recherche : questions associées et intentions ;
- Reddit / forums / commentaires : objections et problèmes récurrents ;
- avis produits / services : problèmes concrets que les clients répètent.

La recherche sociale doit être menée **uniquement sur des contenus publics et accessibles**. Ne jamais prétendre avoir « scrapé » une plateforme si l'accès réel ne le permet pas.

Google Trends est utilisé comme signal d'intérêt, jamais comme mesure directe de ventes.
TikTok Creative Center et Meta Ad Library servent à étudier les tendances et les créatifs, pas à conclure qu'un produit est rentable.

## 3.3 Recherche minimum

Avant rédaction, constituer :

- 8 à 20 sources sérieuses selon la complexité ;
- au moins 2 à 3 sources primaires lorsque le sujet comporte des faits sensibles ou évolutifs ;
- 5 à 15 observations marché/social lorsque cela est pertinent ;
- 2 à 6 vidéos utiles maximum ;
- une liste des 10 questions / blocages les plus fréquents ;
- une liste des erreurs fréquentes ;
- une liste des outils / plateformes incontournables ;
- un relevé des informations susceptibles de devenir obsolètes.

## 3.4 Matrice de preuve

Pour toute information sensible, maintenir une matrice :

| Claim | Source | Date | Niveau | Risque | Date de revue |
|---|---|---|---|---|---|

Risque :
- faible : méthode stable ;
- moyen : outil / tarif / fonctionnalité ;
- élevé : juridique, fiscal, médical, sécurité, réglementation, chiffre actuel.

Aucune affirmation à risque élevé ne doit apparaître sans source suffisante.

# 4. ADAPTATION AU DOMAINE

Le moteur reste identique, mais la profondeur documentaire change selon le domaine.

## Administratif / fiscal / juridique
Privilégier les sources officielles, dater les règles et distinguer clairement :
- loi ;
- doctrine ;
- pratique ;
- interprétation ;
- recommandation.

## Santé / bien-être / nutrition / sport
Privilégier organismes de santé, recommandations officielles et littérature scientifique pertinente.
Ne jamais transformer un guide en diagnostic médical personnalisé.

## Réparation / bricolage / automobile / électronique
Privilégier :
- documentation constructeur ;
- manuels de service lorsque légalement disponibles ;
- consignes de sécurité ;
- guides techniques reconnus.
Identifier clairement les opérations à risque qui exigent un professionnel.

## Langues / apprentissage
Utiliser :
- cadres de référence ;
- ressources pédagogiques reconnues ;
- contenus natifs ;
- exercices ;
- audio / vidéo ;
- progression mesurable.

## Mode / style / cuisine / créatif
Privilégier :
- règles pratiques ;
- exemples visuels ;
- erreurs typiques ;
- mise en situation ;
- outils / références ;
- exercices d'application.

## Business / e-commerce / plateformes
Privilégier :
- documentation officielle des plateformes ;
- statistiques sectorielles ;
- réglementation ;
- recherche marché ;
- outils de mesure ;
- acquisition ;
- rentabilité.

# 5. ARCHITECTURE D'UN SER GUIDE

Objectif : **28–32 pages cibles, 35 maximum**.

Le nombre de pages peut varier selon le sujet, mais le rythme doit rester compact.

## Bloc A — Entrée

### Page 1 — Couverture
- SER Guide XX ;
- titre orienté résultat ;
- sous-titre ;
- millésime si nécessaire ;
- identité visuelle propre à la niche ;
- hook principal ;
- aucun jargon inutile.

### Page 2 — Ce que vous allez obtenir
Répondre immédiatement :
- ce guide est pour qui ;
- ce qu'il va permettre de faire ;
- ce qu'il ne promet pas ;
- durée / effort estimé ;
- outils éventuellement nécessaires.

### Page 3 — Diagnostic express
3 à 7 questions maximum.

Le guide doit pouvoir adapter :
- les recommandations ;
- le chemin ;
- l'ordre de lecture ;
- les alertes.

### Page 4 — Roadmap
Vue d'ensemble :
**Vous êtes ici → voici les étapes → voici le résultat final.**

Le lecteur doit comprendre le parcours en moins de 30 secondes.

## Bloc B — Action

Les pages suivantes correspondent aux étapes réellement nécessaires au sujet.

Chaque étape doit respecter le **module SER Action** décrit ci-dessous.

## Bloc C — Résultat

Terminer avec :
- troubleshooting ;
- erreurs fréquentes ;
- plan d'action ;
- checklist finale ;
- ressources ;
- prochains guides pertinents ;
- sources et date de revue.

---

# 6. MODULE SER ACTION — FORMAT DE CHAQUE ÉTAPE

Chaque étape importante doit contenir, dans cet ordre :

### 1. Objectif
« À la fin de cette étape, vous aurez… »

### 2. Pourquoi c'est important
2 à 5 lignes maximum.

### 3. Faites-le maintenant
Instructions concrètes, numérotées.

### 4. Outils
Afficher les plateformes ou ressources concernées.

### 5. Liens cliquables
Lien direct vers :
- page d'inscription ;
- fonctionnalité ;
- documentation ;
- outil ;
- formulaire ;
- ressource utile.

Éviter de renvoyer uniquement vers la homepage quand une URL plus précise existe.

### 6. Tutoriel / vidéo
Si cela apporte une vraie valeur :
- titre ;
- chaîne / auteur ;
- date si pertinente ;
- pourquoi regarder ;
- lien ;
- timestamp utile si identifiable.

### 7. Exemple
Montrer le résultat attendu.

### 8. À éviter
Erreur fréquente.

### 9. Checkpoint
« Ne passez pas à la suite tant que… »

### 10. Case à cocher
Permettre au lecteur de marquer l'étape comme terminée.

---

# 7. INTERACTIVITÉ

Le web-book est le produit principal.

Le PDF est un export propre pour lecture / archivage / impression.

Fonctions à utiliser lorsque pertinentes :

- progression globale ;
- sommaire ouvrable ;
- étapes dépliables ;
- checklists sauvegardées localement ;
- diagnostic initial ;
- branchement conditionnel ;
- calculateurs ;
- score ;
- comparateurs ;
- champs de notes ;
- todo list ;
- boutons externes ;
- retour à l'étape précédente ;
- « reprendre où j'en étais ».

Ne pas ajouter une fonction interactive uniquement pour impressionner.

Chaque interaction doit réduire une friction ou faciliter une décision.

# 8. DESIGN SYSTEM SER

## 8.1 Invariants de marque

Doivent rester cohérents dans toute la collection :

- lisibilité élevée ;
- mise en page éditoriale premium ;
- beaucoup d'air ;
- typographie nette ;
- sections courtes ;
- cartes et encadrés ;
- progression visible ;
- CTA compréhensibles ;
- ton humain ;
- absence de look « générateur IA générique ».

Typographies recommandées :
- titres : Manrope ou équivalent moderne ;
- texte : Inter ou équivalent lisible ;
- chiffres / calculateurs : IBM Plex Mono lorsque pertinent.

## 8.2 Couleurs

**Ne jamais recopier automatiquement la palette d'un autre guide.**

Pour chaque sujet, créer une palette propre comprenant :

1. fond principal ;
2. fond secondaire ;
3. couleur structurelle sombre SER ;
4. accent propre à la niche ;
5. accent doux ;
6. alerte ;
7. cartes.

Exemples de logique :
- administratif : marine / cyan ;
- e-commerce : crème / graphite / vert commerce ;
- bricolage : sable / graphite / terre cuite ;
- langues : papier chaud + accent culturel adapté sans cliché ;
- mode : tons éditoriaux / textile ;
- tech réparation : graphite / acier / accent électrique ;
- cuisine : crème / ingrédients / accent chaleureux.

La palette doit être justifiée par :
- univers du sujet ;
- émotions utiles ;
- lisibilité ;
- cohérence avec les 3 visuels sociaux.

## 8.3 Imagerie humaine

Priorités :
- objets réels ;
- mains ;
- matières ;
- environnement de travail ;
- détails du métier ;
- situations crédibles ;
- photographie éditoriale.

Éviter :
- cerveau IA ;
- circuits lumineux ;
- humanoïdes ;
- néons futuristes ;
- imagerie SaaS générique ;
sauf si le sujet l'exige réellement.

## 8.4 Repères visuels connus

Utiliser, lorsque pertinent :
- logos ;
- icônes ;
- interfaces ;
- noms de plateformes ;
- outils connus.

Objectif psychologique :
**« je reconnais cet outil → je comprends où je suis → je reste engagé. »**

Règle juridique :
- utiliser uniquement les assets officiels si leurs conditions le permettent ;
- respecter les brand guidelines ;
- ne jamais modifier un logo ;
- ne jamais laisser croire à une affiliation ou un sponsoring ;
- si l'usage du logo n'est pas clairement autorisé, utiliser le nom de la plateforme sous forme de badge texte neutre.

# 9. UX / PSYCHOLOGIE DE LECTURE

Le guide doit donner une impression de progression continue.

## Principes

### Early win
Le lecteur doit obtenir une première amélioration / décision utile dans les 5 à 10 premières minutes.

### Chunking
Une page = une décision ou une étape principale.

### Progressive disclosure
Les détails secondaires sont repliables ou placés après l'action principale.

### Familiarité
Utiliser des repères connus :
- logo de l'outil ;
- capture ou représentation d'interface lorsque légalement possible ;
- vocabulaire réellement utilisé par la plateforme.

### Réduction de charge mentale
Ne jamais afficher 25 décisions en même temps.

### Action immédiate
Chaque 1 à 2 pages doit idéalement contenir quelque chose à :
- faire ;
- cocher ;
- calculer ;
- ouvrir ;
- vérifier ;
- décider.

### Progression visible
Toujours montrer :
- étape actuelle ;
- pourcentage / progression ;
- prochaine étape.

# 10. LIENS EXTERNES

Les liens font partie du produit.

Ils doivent être :

- cliquables ;
- vérifiés avant publication ;
- précis ;
- récents ;
- utiles ;
- attribués.

Types :
- inscription ;
- dashboard ;
- documentation ;
- formulaire ;
- simulateur ;
- service public ;
- vidéo ;
- guide officiel ;
- outil ;
- ressource.

Afficher idéalement :
- nom ;
- fonction ;
- domaine ;
- éventuellement date de vérification.

Tous les liens doivent être retestés avant publication d'une nouvelle édition.

---

# 11. VIDÉOS

Ajouter des vidéos uniquement lorsqu'une démonstration est plus efficace que du texte.

Priorité :
1. chaîne officielle ;
2. organisme reconnu ;
3. expert identifiable ;
4. tutoriel communautaire reconnu.

Éviter :
- vidéos trop anciennes sur des interfaces évolutives ;
- promesses sensationnalistes ;
- « hacks » non vérifiés ;
- contenu qui contredit les sources primaires.

Pour chaque vidéo intégrée :
- titre ;
- chaîne ;
- lien ;
- date ;
- durée approximative ;
- ce que le lecteur doit regarder ;
- timestamp utile si possible.

Maximum recommandé : 2 à 6 vidéos réellement utiles par guide.

# 12. PONTS ENTRE SER GUIDES

Un guide ne doit jamais promouvoir un autre guide « parce qu'il faut vendre ».

Les recommandations doivent être **contextuelles**.

Trois types possibles :

### Prérequis
« Avant cette étape, ce guide peut vous aider à… »

### Complément
« Si vous voulez approfondir X… »

### Étape suivante
« Maintenant que vous savez faire X, la suite logique est Y. »

Exemples :
- e-commerce → micro-entreprise → fiscalité → TikTok Shop ;
- anglais débutant → conversation → immersion / voyage anglophone ;
- bricolage plomberie → diagnostic fuite → rénovation salle de bain ;
- démontage console → entretien électronique → soudure débutant ;
- habillement → couleurs → capsule wardrobe → entretien textile.

Règles :
- 0 à 3 recommandations maximum ;
- aucune recommandation hors sujet ;
- positionner le lien au moment logique, pas uniquement à la fin ;
- si l'utilisateur possède déjà le guide : afficher « Ouvrir dans ma bibliothèque » ;
- sinon : « Découvrir ce guide ».

Chaque lien doit préciser **pourquoi** le guide est recommandé.

# 13. SOCIAL — PACK INSTAGRAM OBLIGATOIRE

Chaque SER Guide produit exactement **3 visuels de lancement**.

Format principal :
**1080 × 1350 px — 4:5**

Même DA que le guide.

## VISUEL 01 — HOOK

C'est :
- l'image principale du post Instagram ;
- la couverture du guide dans la boutique ;
- la vignette de la bibliothèque ;
- le visuel principal dans les sliders du site.

Objectif :
arrêter le scroll.

Structure :
- phrase courte ;
- problème concret ;
- forte lisibilité ;
- image / objet photographique lié au sujet ;
- identité SER discrète ;
- aucune surcharge.

Exemples de structures :
- « 7 erreurs avant de… »
- « Avant de faire X, vérifiez ça. »
- « Pourquoi X ne fonctionne pas comme vous le pensez. »
- « Le guide pour passer de X à Y. »

Le hook est choisi après recherche des formulations utilisées dans la niche.

## VISUEL 02 — VALEUR

Doit apporter immédiatement quelque chose :
- mini checklist ;
- chiffre utile ;
- méthode ;
- comparaison ;
- erreur ;
- avant / après logique ;
- mini roadmap.

La personne doit pouvoir sauvegarder l'image même si elle n'achète pas immédiatement.

## VISUEL 03 — PRODUIT

Présenter :
- le guide ;
- résultat ;
- contenu ;
- bénéfices ;
- CTA ;
- éventuellement prix.

Le visuel doit ressembler à une vraie campagne éditoriale, pas à un mockup IA générique.

## Caption

Fournir automatiquement :
- hook texte ;
- caption ;
- CTA ;
- alt text ;
- hashtags ciblés raisonnables ;
- lien / UTM prévu pour la bio ou landing.

---

# 14. RELATION SITE ↔ EBOOK ↔ INSTAGRAM

L'expérience doit être cohérente.

## Instagram
Visuel 1 = découverte.

## Landing
Le même Visuel 1 = reconnaissance immédiate.

## Fiche produit
Même titre, promesse et palette.

## Ebook
Même univers graphique.

## Compte utilisateur
Le même Visuel 1 représente le guide acheté.

Ainsi :
**Instagram → site → paiement → bibliothèque → lecture**
doit ressembler à un seul produit continu.

# 17. PÉREMPTION ET MISE À JOUR

Chaque guide doit recevoir un niveau de volatilité.

## Très volatile
Plateforme, logiciel, réseau social, prix, fiscalité, réglementation évolutive.
Revue recommandée : 30 à 90 jours.

## Moyenne
Marché, méthode, matériel.
Revue : 3 à 6 mois.

## Faible
Apprentissage stable, techniques fondamentales.
Revue : 6 à 12 mois.

La date d'édition doit être visible.

Si une information devient incertaine :
- ne pas la masquer ;
- indiquer qu'elle doit être vérifiée ;
- renvoyer vers la source actuelle.

---

# 18. ACCESSIBILITÉ

Minimum :

- texte principal ≥ 16 px sur écran ;
- contraste suffisant ;
- boutons tactiles ≥ environ 44 px ;
- texte alternatif pour images informatives ;
- navigation clavier ;
- liens compréhensibles hors contexte ;
- ne pas utiliser uniquement la couleur pour transmettre une information ;
- version mobile testée.

---

# 19. QUALITÉ DU CONTENU

Interdit :

- remplissage ;
- répétition ;
- phrases génériques de type « soyez régulier » sans expliquer comment ;
- chiffres sans date ;
- liens morts ;
- conseils sans contexte ;
- faux témoignages ;
- fausses statistiques ;
- faux avis ;
- fausses affiliations ;
- pseudo-expertise ;
- citations fabriquées ;
- promesses financières garanties.

Obligatoire :

- exemple concret ;
- étape suivante claire ;
- source lorsque nécessaire ;
- action ;
- résultat attendu ;
- signal d'arrêt lorsque le lecteur n'est pas prêt à continuer.

# 20. QA — TEST AVANT PUBLICATION

Un guide n'est « READY » que si tous ces points sont validés.

## Recherche
- [ ] sources suffisantes
- [ ] faits sensibles vérifiés
- [ ] dates indiquées
- [ ] tendances séparées des faits

## Contenu
- [ ] promesse claire
- [ ] progression logique
- [ ] aucune section de remplissage
- [ ] résultat final atteignable
- [ ] erreurs / troubleshooting présents
- [ ] 30 pages environ
- [ ] jamais >35 pages

## Liens
- [ ] tous les liens fonctionnent
- [ ] inscription / outils vont aux bonnes pages
- [ ] vidéos accessibles
- [ ] liens officiels prioritaires

- [ ] première victoire rapide
- [ ] progression visible
- [ ] checklists utiles
- [ ] aucune surcharge

# 23. RÈGLE DE COHÉRENCE DE COLLECTION

Tous les SER Guides doivent avoir l'air de venir de la même maison d'édition, sans être identiques.

**Même ADN :**
- structure ;
- typographie ;
- qualité ;
- ergonomie ;
- ton ;
- logique d'action ;
- signalétique SER.

**Personnalité différente :**
- palette ;
- photographie ;
- objets ;
- accent ;
- vocabulaire ;
- plateformes ;
- exercices ;
- références.

Un guide « apprendre le chinois » ne doit pas ressembler visuellement à « réparer une PlayStation ».
Mais on doit reconnaître immédiatement qu'ils appartiennent tous les deux à SER Guides.

# 24. RÈGLE DES LOGOS ET MARQUES

Les logos servent de **repères cognitifs**, pas de décoration.

Utiliser un logo seulement si :
- l'outil intervient réellement ;
- il aide le lecteur à identifier l'étape ;
- l'usage respecte les règles officielles de marque.

Ne jamais :
- recolorer arbitrairement ;
- déformer ;
- recréer ;
- intégrer le logo dans le logo SER ;
- suggérer un partenariat inexistant.

Si une marque interdit ou restreint l'utilisation de ses assets :
utiliser un **badge texte** portant le nom du service.

# 25. RÈGLE « INTELLIGENCE DU GUIDE »

Avant de finaliser chaque page, poser cette question :

> « Si je supprime cette page, le lecteur perd-il une décision, une compétence ou une action nécessaire ? »

Si la réponse est non, supprimer la page.

Avant de finaliser chaque lien :

> « Est-ce que ce lien aide réellement le lecteur à accomplir l'étape maintenant ? »

Avant de recommander un autre SER Guide :

> « Est-ce réellement la prochaine brique logique du parcours de cette personne ? »

Avant d'ajouter un outil :

> « Est-ce le meilleur outil pour le besoin, ou juste un nom connu ? »

# 27. CRITÈRE ULTIME

Le produit est terminé uniquement si une personne peut :

1. ouvrir le guide sans connaître le sujet ;
2. comprendre immédiatement ce qu'elle va obtenir ;
3. savoir quoi faire en premier ;
4. suivre les étapes sans chercher elle-même toutes les ressources ;
5. accéder aux bons outils ;
6. vérifier les informations importantes ;
7. voir sa progression ;
8. résoudre les blocages courants ;
9. terminer avec un résultat concret ;
10. savoir naturellement quelle est sa prochaine étape.

**SER Guides = comprendre → vérifier → agir → obtenir un résultat.**
